# SQT2 考场规格(方波随机深槽 v2;第九考场,交 Codex 复审后预检)

日期:2026-08-18。地位:V3.2 终审后的换考场提案。**未过复审与 headroom 预检前,
不进入任何特征/BC/PPO 阶段(铁律)。**

## 1. 设计动机(一段话)

v3.x 验尸出的两个死因:①真实风的平滑爬坡让"当前绿电斜率"泄漏未来 → 预报冗余;
②富窗口占多数,时移机会稀薄 → 中位 headroom 1.8–4.4% < 认证底。SQT2 用信息论手段
同时封死两者:绿电二值(满/零),全部绿 DC **同步**进入**随机时长**深槽,槽长分布
跨预报视野与 slack 两侧——短槽(等得起,值得等)与长槽(等不起,该跑棕电)在
**当前状态下完全同观**(绿电都是 0),只有预报能区分。当前态信息 = 0,预报信息 =
决策全部所需,这是构造性的载重保证。

## 3. 负载

起点沿用 `v3b_n1200.csv`(slack 中位 2066/p95 2918,与槽分布天然交叠);
标定阶段检查两条,不满足则调 trace:
(a) control(不等待,强空间)完成率天花板 ≥99.5%(本战役合同教训);
(b) 绿窗总容量 ≥ 总负载 × 1.2(时移有物可移)。

## 4. Headroom 预检协议(铁律实例化;通过才谈 RL)

**两段式**:
- **粗筛**(贪心路由 + SlotAllocator 当空间基线,~2h):三臂
  ①不等待 ②**当前态门**(绿电=0 且预算>0 则等——v3 从未设过的关键对照)
  ③clairvoyant 聚合门(H1a 式,读真值序列,θ/margin 由标定冻结);
  粗筛 clairvoyant 中位 <8% 直接放弃考场,不再烧盲 PPO。
- **正检**(盲 PPO 600k 作强空间基线,协议同 H1c:配对 offset、
  完成率有效门、10000 排尽 + 7200 快照、全窗口计入):

**判决门(预注册,不挪)**:
1. clairvoyant vs 不等待:中位改善 ≥10% ∧ ≥8/10 有效同向 ∧ 双臂完成合同;
2. **clairvoyant vs 当前态门:≥7/10 offset 更优 ∧ 中位差 ≥3pp**
   ——"未来信息打赢现在信息"的操作化定义,不满足即预报冗余,考场作废;
3. anti(A′ 容量镜像)使 clairvoyant 收益消失或反转(内容依赖证明)。

## 5. 继承的护栏与资产

判决器(pair_verdict/级联诊断)、分层解码、A′ 扰动、反事实需求特征、
preflight 全套 + 新增两项(control 天花板、当前态门冗余检查)。

## 6. 排期与止损

生成+配置+preflight 半天;标定 2–4h;粗筛 2h;正检(盲 PPO + 阶梯)~1.5 天。
**任何一段不过线即封存 SQT2,记入负结果账本,论文不受影响**(主表不依赖任何 v3.x/SQT)。

# 修订 → SQT2.1(08-18,Codex "修改后批准";六条全采纳)

## R1 时长分布(修正算术矛盾与长度偏置)

原 ON U[300,900]/OFF U[300,4500] 期望绿占比 = 600/3000 = **20%**,与 55–65% 目标
自相矛盾;且按时间加权(长槽更易被撞见),短于 slack 中位的槽只占 OFF 暴露 ~21%。
**改为预注册双峰**:
- OFF:80% 短槽 U[300,1500](均值 900) + 20% 长槽 U[2700,4500](均值 3600)
  → 短/长槽时间权重各 720,作业撞见约各半;
- ON:U[1500,2700](均值 2100);
- 期望绿占比 2100/(2100+1440) = **59.3%** ✓。

## R2 当前态门判据加强

oracle vs 当前态门:**≥8/10 有效窗口更优 ∧ 配对中位相对碳改善 ≥5%** ∧ 双臂完成
≥99.5%。新增解释指标 **forecast share** =
(C_current-gate − C_oracle)/(C_no-wait − C_oracle),**中位 ≥0.5**
(时间收益至少一半来自未来信息,而非"见零即等")。

## R3 anti 主判据 = oracle vs anti

**oracle 相对 anti 中位省碳 ≥5% ∧ ≥8/10 有效同向 ∧ 全有效窗口计入**(不筛同动作
窗口)。anti vs no-wait 是否反转仅作辅助诊断(错误等待也可能有队列平滑收益)。

## R4 表述修正 + 暴露检查

"信息论级保证"改为:**槽开始时,短槽与长槽共享完全相同的历史与当前观测;未来
时长只通过 forecast source 暴露**(recurrent 策略可记槽龄,剩余时长与槽龄相关,
队列/wait_age 也可能泄漏——不声称当前态零信息)。preflight 新增:
- wait-worthy / not-worth 的 MI 暴露比例均在 35–65%;
- 10 个评测窗口须覆盖 **≥8 个不同槽实例**;
- **序列延长**:均值周期 ~3540s,15012 行仅 ~4 周期不够 → 生成 **90000 行**,
  `green_episode_offset_range` 扩至 **72000**((72000+10000)/3540 ≈ 23 周期,
  窗口起点充分分散)。配对同前缀短/长槽片段列为 v2.2 可选增强。

## R5 预测来源声明

随机槽长不可能由纯历史模型(TimeCAP)预测。headroom 阶段用 **oracle schedule**
(godeye 读 CSV);后续 forecast 臂用**可访问外生计划的合成预报器**,转折时间误差
预注册;论文声称口径 = "外部可预测事件/调度预报",不得称"从功率历史预测随机未来"。

## R6 绿窗容量的正确量纲

护栏改为可执行 MI 定义:
green_executable_MI = Σ_ON行 Σ_绿DC min(G_d / W_per_PE_eff, PE_d) × MIPS × Δt
≥ 1.2 × Σ 作业 MI(W_per_PE_eff = idle 分摊 + 动态每 PE,取自 HostProfile 常数)。
标定阶段实算并写入 artifact,不比较 W 与 MI。

## 标定阶段发现(08-18 深夜):三体约束冲突,需要 workload 层面的设计决定

### 已修复的仪器问题
- **锚点与 env 固定步长的冲突**:env 闭卷日程步长固定 1009,range=180000 时
  10 个 episode 只覆盖序列开头 7%。修复方案:预注册锚点 episode 集
  K={17m: m=0..9} → offset=17153m 均匀铺满(评测器加快进 reset 支持,待实现)。

### 未解的设计冲突(参数网格全灭的根因)
即便锚点铺开,worthy 仍=1.00。机制链:
1. 到达只发生在窗口前 5562s → 每窗口仅 ~1.6 个周期;
2. 长槽占槽数 20% → 每窗口期望 0.3 个长槽,且只有**在窗口内开始**的长槽才提供
   "早段到达"(残余等待 > 预算)的 not-worth 暴露,概率 ~0.28/窗口;
3. 到达更常撞进槽**尾段**(残余小)→ 几乎全 worthy;
4. 绿占比带(0.55–0.65)+ 结构分离(long_min>slack_p50)+ 到达跨度 5562s +
   当前 trace 的 slack 剖面(p5=1290,全员等得起 ~1300s)四者联立**过约束**:
   提高长槽频率必砸绿占比,缩 ON 亦然。

### 设计提案(待 Codex 裁定):not-worth 类改由 slack 异质性提供
当前 trace 的 slack 单峰(p5=1290)使"短槽人人等得起"。**提案:v3b trace 变体,
slack 双峰**——约 40% 作业紧 slack U[200,900](短槽残余也等不起 → not-worth),
60% 保持现分布(等得起 → worthy)。暴露平衡由【作业×槽】交互提供而非稀有长槽,
标定自由度解耦:绿占比归槽分布管,暴露平衡归 slack 混合比管,长槽只负责
"超视野"类。这也让逐作业门有真正的作业间区分度可学。
代价:新 trace 生成 + control 完成率天花板复检。

**在此裁定前,SQT2 标定暂停;不动任何门槛。**
