## 2. 反常一:s30 池化反超 godeye = 池化均值的重尾假象

逐 run(97 格 × 3 窗 = 291)分解:

    s30 仅在 47.8% 的 run 胜过 godeye,中位相对差 0.0%
    池化净胜全部由 10 个最幸运 run 承载(其和为净胜的 112%)
    逐格归一保留率中位:s05 100.0% → s15 100.0% → s30 100.0% → s60 97.5%(完美单调)

结论:噪声轴在中位口径下严格单调;违反单调的是**度量**——池化均值被格间碳量级
(divisor 跨 16 倍,格碳差 ~10 倍)支配,少数大格的冻结噪声场运气顶穿了池化线。
个别 run 中噪声助益的机制是启发式规划器的贪心次优(完美信息导致过度集中,抖动意外摊铺),
这再次印证 curve planner 不得称 optimal 的措辞纪律,但它不构成系统性反超。

## 3. 反常二:shuffle 的 91.9% 是同一口径病,逐格口径为 73.7%

    池化均值口径   shuffle 保留 91.9%(判据线 50%,故判失败)
    逐格归一中位   73.7%,IQR [23.4%, 93.9%];仅 21.6% 的 run 胜 godeye,中位劣 37.4%

即负控确实摧毁了约 26% 的中位收益,但仍未到 50%。科学含义(诚实陈述):该考场的
oracle-盲臂差距中,**"获准等待+摊铺"的机械价值占大头,时机信息的净价值中位约 26%**。
Stage A 的门无法区分这两者;负控判据正是为此而设,它工作了。

## 4. 反常三:timecap_cal 的 −41% 被一个可证的设计缺陷放大

实测真实 TimeCAP(部署 checkpoint,2020 数据,相同锚点)的跨风机残差相关:

    T12–T36  r=0.862      T12–T95  r=0.826      T36–T95  r=0.744

真实误差强共模(同片天气、同模型偏差),**保住站点间相对排名**;而 timecap_cal v1 的
实现给各站抽独立噪声场(跨站相关=0),专门打乱空间排名——对路由型规划器是最毒的腐蚀。
故 −41% 中有真实成分(σ_rel=1.19 的质量确实差)但严重度被高估。anti 逐站独立无妨
(其使命即摧毁);timecap_cal 的使命是忠实,v1 不忠实。
