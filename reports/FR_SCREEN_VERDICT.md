## 直接回答工单的关键问题

> 残差 ΔR² 高 ⇒ 信息一直在,只是被淹没了 ⇒ 有救,而且是特征工程能救

**成立**,但要加三条限定:

1. **信息住在 1–24 小时视界**,不在 30 分钟。现役 `short_mean`/`short_trend`
   看的正是 **30 分钟,ΔR² 仅 0.041 —— 低于工单自己的 0.05 阈值**。
2. **现役 long 特征其实抓住了长视界信息**(H=144 上 incumbent4 ΔR²=**0.724**)。
   所以不能说"现役特征把信息丢了";它们在长视界上是有效的。
3. **比较量远弱于绝对量**:决策是比较性的(送哪个 DC / 等不等),而
   cross-DC 差分在短视界上只有绝对量的 **1/6–1/10**
   (H=3:0.004 vs 0.041;H=6:0.016 vs 0.086),H=144 才升到 0.367。
   DC2(单涡轮)在所有短视界上 cross-DC 信号 ≈ 0。

## 三条排除掉的病因(全部如实记录)

- **不是 oracle 泄漏**:pred 与真值有真实误差(h=1 RMSE 210 kW 对真值
  sd 907 kW,corr 0.977;max|pred−act| 达 3075 kW)。分析有效。
- **不是滞后错位**:最佳滞后诊断在 H=3 与 H=24 上**均为 lag=0**,契约
  (`pred[h] = T0+1+h`)正确。档案里"−8 步"是仿真回路里的缓存陈旧,不是
  模型契约问题。
- **不是缓存陈旧**(我自己提的假设,**被自己的数据推翻**):
  `forecast_every: 6` 下策略最旧看到 5 行(50 分钟)前的预报,但增量信息
  保留 **94.8% / 95.1% / 97.6% / 99.5%**(H=3/6/12/24)。陈旧不是病因,
  调小 `forecast_every` 不会有帮助。

## 一处方法学说明(必须讲清)

`resid_pred_minus_persistence` 与 `pred_mean_H` 的 ΔR² **逐位相同**。
原因:blind 已含 persistence(当前绿电),线性模型下"预报"与"预报−persistence"
张成同一空间。**这不是 bug** —— 恰恰说明**ΔR² over 含 persistence 的 blind
本身就是残差检验**,工单想问的问题已被主表直接回答。若要单独考察残差,
需换非线性模型或考察策略侧的特征缩放,那属于另一件事。

## 这个结果与既有结论的关系(不冲突,但要分清)

它**推翻**的是"预报器/视界不带增量信息"这一支。它**不推翻** TB12 表示
能力审计 Run 2,因为两者量的不是同一件事:

| | 本轮(C-regime + TimeCAP) | TB12 表示审计 Run 2 |
|---|---|---|
| 问题 | 预报通道能否预测**未来绿电** | 预报通道能否判别**该不该等这个作业** |
| 答案 | **能,而且很强**(≥1h 视界) | **不能**(分歧作业上无可泛化增量) |

两者可同时成立:精确知道未来绿电,并不等于知道等待对**某个具体作业**
是否划算 —— 如果该作业的 slack 够不到绿窗,或各 DC 风况共模变化使
**比较性**决策不受影响。本轮数据对后者给出了直接的量化线索(见上文第 3 条:
比较量在短视界弱 6–10 倍)。
