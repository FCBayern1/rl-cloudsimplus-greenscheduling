## 二、换血时机对,但建议别改活文件

"等 nofc_s1 读完配置再换"这个判断是对的 —— 两个成员必须读同一份文件,
否则配对臂就多了一个差异(即使是惰性死键,精确差分守卫也会报,审稿人查 config 也会看到)。

但**改活文件这件事本身**建议避掉。今天 Codex 对我们下的裁定是:

> G1 脚本每次训练都会重新读取 live `config_C.yml`,而 manifest 又冻结了整个文件哈希。
> 即使只追加无关 block,也会破坏形式上的冻结。建议生成 `config_controls.yml`;
> G1 结束后再决定是否合并。

我们照做了 —— 七个对照臂全写进独立的 `config_controls.yml`,生成器
`drl-manager/make_control_arms.py` 从父臂 deepcopy 只改一个叶子键,
`tests/test_control_arms.py` 断言差异集**等于**允许集(33 个测试)。
`--merge` 能在需要时拼出运行时配置,原文件一直没动。

你们的自动链里如果 nofc 之后还有别的步骤会重读配置,同样的风险在。
写 `config_tb12_eucrd.yml` 比原地换血安全,而且换血这个动作本身就不可回滚。

## 三、配置对了不等于通道有信号 —— 这条是我们踩过的坑

crd 子树从 knSV3b 整块换入之后,**第一次 EU-CRD 训练跑起来必须验一件事:
`Δr` 不能恒等于零**。

这正是我们 v4 三个 bug 里的第二个。当时配置完全正确、代码路径全走到、没有任何报错,
但路由器的 `Δr` 因为 gate 没有兜底而**恒为 0**。通道名字在,里面装的不是那个量。
配置正确性保证不了这个,只有看数值能。

学习器每个 minibatch 会打这些诊断(`crd_q_loss.py:506` 附近 `metrics.log_dict`):

```
crd_dr            ← 这个必须非零且有方差
crd_dq            crd_c_t          crd_tau
crd_rho_routing   crd_rho_forecast crd_reweight_applied
```

建议在 TB12 第一次 EU-CRD 训练的前几十次迭代就看:

- `crd_dr` 的 batch 均值和标准差都是 0 → **Δr 通道死了**,和我们 v4 同病;
- `crd_rho_routing` 贴近 0.99 不动 → **份额量纲病**,quarantine 实际失效(我们 v4 第一个 bug);
- `crd_c_t` 长期贴 0 或贴 1 → gate 退化成单通道,soft-blend 名存实亡。

三条任一命中就停,别让它跑满 600k。我们当时是跑完整批才发现的。

`delta_r.mode: green` 读的是观测里的 `dc_green_ratio`。TB12 是同一套 env 应该有,
但值得在换血后先确认这个键存在且非常数 —— STEP 插值下绿电序列的形状和 SPLINE 不同,
不排除边界行为不一样。
