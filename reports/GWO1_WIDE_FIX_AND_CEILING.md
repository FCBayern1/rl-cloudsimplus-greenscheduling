## 1. 哨兵值 bug（5080 读代码定案，无需重跑）

```python
# 修复前 TroughIndex.query()：槽外返回哨兵
return False, 0.0, 0.0          # (in_trough, age, residual)

# gate_flags()
elif mode == "clairvoyant":
    flags[i] = residual <= budget        # 0.0 <= budget 恒真
```

修复前的复现输出：

```
绿窗 row=5000 -> (False, 0.0, 0.0)
  宽门 naive        绿窗内 hold=True
  宽门 hazard       绿窗内 hold=True
  宽门 clairvoyant  绿窗内 hold=True      ← 三个臂全部恒真
```

**宽门下三个臂在绿窗内全部无条件延迟。** 那三格测的是"把绿窗到达的作业全部推走"，不是假设本身。这与观察到的现象逐字吻合：延迟量涨 5.1 倍、blmax 顶死 200、碳 +25.65%。

### 1.1 修复后的绿窗语义（5080 给的表）

| 臂 | 槽内（不变） | 绿窗内（新增） |
|---|---|---|
| nowait | 永不等 | 永不等 |
| naive | `budget > eps` → 等 | **不等** —— 零信息策略看不到剩余绿电，这是诚实的零信息基线 |
| hazard | `P(槽在预算内结束｜age) ≥ q*` | `P(剩余绿电 < runtime｜绿窗龄) ≥ q*`，用注册的 ON~U[1500,2700] |
| clairvoyant | `residual ≤ budget` | `rem_green < runtime` **且** `rem_green + next_trough ≤ budget` |

clairvoyant 那条是"当且仅当此刻是剩余预算窗口内碳最小的释放时刻才释放"在碳恒定下的退化形式，接 TVCI 后仍成立。

**一条关键性质**：这样定义后 **nowait 是 clairvoyant 自己问题的可行解**，所以 clairvoyant 数学上不可能比 nowait 差，除非受 cap/拥堵干扰。**修复后若仍出正号，那就是还有别的 bug。**

### 1.2 附带修正

- `residual` 槽外改为 **`None`** 而不是 `0.0`。同类误用现在是 `TypeError` 而不是静默通过。**没有用 `-1`**，因为 `-1 <= budget` 仍是合法比较，只有 `None` 会当场炸。
- `ON_LO`/`ON_HI` 从 `gen_sqt2` 导入，不在 prescreen 里抄第二份。
- **我自己有两个测试把 bug 写进了断言**：`test_query` 断言 `(False, 0.0, 0.0)`，`test_wide_defers_outside_trough` 断言 naive 在绿窗里会延迟。两条都已重写并在 docstring 里注明当时错在哪。

### 1.3 `--ppo-arms`：接口不允许你做正确的事

原来 ppo 底座写死跑全部四臂，`--sentinel-arms` 只对 greedy 生效 —— **"2 臂 × 3 锚"在 CLI 层面根本表达不出来**。

这和哨兵值 bug 是同一族问题：**默认值把错误变成了沉默**。`residual=0.0` 让"没有信息"沉默地变成"残余为零"；`arms = all_arms if b == "ppo"` 让"我只想跑两个臂"沉默地变成跑四个。两者都不报错，都给出看起来合理的数字。

## 3. 碳口径硬上界 12.95%（独立互核）

出数的人不做唯一核对人。`verify_gwo1_green_bound.py` 从 schedule + trace 直接算，**不读 5080 的产物** —— 读了就退化成复述。用的是 `gate_flags` 里 clairvoyant 判据的同一定义。

| | 5080 | 3060 独立复算 |
|---|---:|---:|
| 总 MI | 3.0421e+11 | **3.0421e+11** |
| nowait 棕电 MI | 9.7377e+10 (32.0%) | **9.7377e+10 (32.0%)** |
| 可搬走棕电 MI | 1.2607e+10 (4.14%) | **1.2607e+10 (4.14%)** |
| **碳口径硬上界** | **12.95%** | **12.95%** |

### 3.1 推导

碳 ≈ 棕电 MI × 棕因子（绿因子只有棕的 1/55，忽略它让上界略偏大 = 保守）：

$$\text{上界} = \frac{\text{宽门可搬走的棕电 MI}}{\text{nowait 下的棕电 MI}} = \frac{1.2607\times10^{10}}{9.7377\times10^{10}} = 12.95\%$$

### 3.2 一处我推错方向的记录

我一度把 6.09%（绿窗决策集 MI 口径）换算到全 episode MI 得 4.14%，并主张"收紧对我们有利"。**这是错的。** 碳差的分母只有棕电那 32%，不是全部 MI。4.14% 会过紧三倍，**把真实机制效应误判成 bug** —— 与我担心的方向相反。

**碳口径的线比 MI 口径【宽】，方向别记反。** 已钉进测试。

### 3.3 互核抓到 5080 一个真 bug

分母对不上（1.901e11 / 7577 次 vs 2.0597e11 / 8165 次）。根因是 5080 那份 `green_intervals` 用 `zip(iv, iv[1:])` 遍历相邻两槽之间，**把首段绿窗（row 0 → 第一个槽）整段丢了**。修完 n=8165，与本机逐点一致。

本实现恰好没踩，但踩法不同，两个边界都已钉进测试：

- **首段**：`prev` 从 0 起累加，自然保留。
- **尾段**：**保留**在 `self.on` 里，但 `next_trough_dur` 返回 `inf`，于是 `rem_green + next_trough <= budget` 恒假 —— 功能上等价于排除，靠结构达成，不需要特判。

### 3.4 场景确认

gwo1 与 SQT2-cal 的上界不同（12.95% vs 10.58%，gwo1 的 runtime ×1.30 使可搬棕电更多）。5080 确认两条跑都是 `--schedule gwo1`，所以**适用的是 12.95%**。最深的 ep79（−7.34%）在两条线下都在界内，结论不受此影响。

### 3.5 上界利用率 —— 比"界内"更有信息

| 锚点 | Δ宽 | 利用率 |
|---|---:|---:|
| 0 | −2.60% | 20% |
| 79 | −7.34% | **57%** |
| 158 | −0.98% | 8% |

**可搬运的棕电大部分没被搬走。** 约束不在"有多少可搬"，而在"等不等得起"（budget）和拥堵。

**但放宽 budget 不是可用的杠杆**（5080 提前拦下，理由成立）：判决量的是 `clair − 最强盲`，而放宽 budget 同时抬高两边，且**盲策略受益更多**（它本来就在盲等，更多预算 = 更多免费机会）。SQT2 的教训正是"预算充裕 + backstop 免费"造就无悔等待，让零信息的 naive 变得不可战胜（clair vs naive 只剩 +0.50%）。**天花板抬高 ≠ 判决改善。** 此条只作为机制解释记录，不作为调参方向；真要动 budget 需要新场景 ID + 全套重认证。

## 5. 天花板测量（进行中）

### 5.1 推论

判决要求 `(clair − 最强盲)/最强盲 ≤ −5%`。**nowait 本身属于盲策略类**，所以 `carbon(最强盲) ≤ carbon(nowait)`。由此：

> `clair vs nowait` 就是整个判决的天花板，且只在"最强盲恰好等于 nowait"这个最宽松情形下才可达。

3 锚下天花板 −2.60%（宽门）/ −1.70%（窄门），**已低于判决线 −5%**。参照 SQT2：那边 clair vs nowait 有 −8.82%，被最强盲（naive）吃到只剩 +0.50%。

### 5.2 为什么先量天花板而不是先建 DP

DP 策略表是最大的一块工程，而它的作用是**把天花板往下压**（找出最强盲）。天花板本身够不着判决线的话，DP 建出来也只是把 −2.6% 压到 −0.5%，纯属白做。**先证假设，再建工程。**

### 5.3 预注册判据（2026-08-20 13:20 冻结，不许事后改）

| 10 锚中位 clair vs nowait | 判定 |
|---|---|
| 优于 −5% 不成立 | gwo1 数学上不可能通过判决，**封档** —— 不建 DP、不跑 held-out、不做 TVCI |
| ≤ −5% | 天花板够高，此时才值得建 DP 去找最强盲 |

### 5.4 为什么必须跑满 10 锚

3 锚散布是 **−0.98% ~ −7.34%，跨度 7.5 倍**，而 **ep79 单独已越过 −5% 判决线**。10 锚中位完全可能落在 5% 两侧任一边。**出数前不做倾向性判断。**

### 5.7 两个正号的分析

5080 的不变量说 clairvoyant 不可能差于 nowait（nowait 是它自己问题的可行解）。
但 ep40 和 ep119 出现正号。按绝对量看，这两格**不是系统性劣化**：

```
ep40  绝对Δ = +0.0046 kg     ep0  绝对Δ = −0.0046 kg     <- 同量级，符号相反
ep119 绝对Δ = +0.0010 kg     (噪声量级)
```

**ep40 是最绿的锚点**（nowait 碳 0.0842，次低的 ep178 是 0.1281）。它的绝对误差与 ep0 完全同量级，
**+5.43% 是小绝对量除以最小分母的产物**，不是机制反转。

**但不变量确实被破坏了，而且我认为原因是不变量本身有一个未言明的前提**：

> "nowait 是 clairvoyant 的可行解"这个论证对**单个作业孤立**成立。
> 但容量是共享的——延迟作业 A 会改变作业 B 的开始时刻。
> `rem_green < runtime and rem_green + next_trough <= budget` 是**逐作业贪心**，
> 它在决定 A 时不知道 B 也会在下一个绿窗起点被释放。
> 所以 clairvoyant **可以**比 nowait 差，代价来自排队耦合而非预测错误。

`blmax` 不支持"拥堵"的简单解释：ep40 的 blmax=172 是全部 10 格里**最低**的，
而它的相对劣化最大。所以耦合发生在绿窗起点的**瞬时并发**上，不是在积压深度上。

## 8. 一个未解决的假设，需要在四门梯子之前处理

绿窗 hazard 臂现在用的 `q*` 来自 5080 的独立绿窗冻结（`gwo1_green_hazard_freeze.json`），**但那次标定的结论是**：

```
never_wait(绿窗内永不等)  acc = 0.9174   ← 最强
green_hazard@0.60          acc = 0.8249   ← 网格内最好，且顶在边界
always_wait                acc = 0.0826
```

**零信息的"绿窗内从不等"打败所有 hazard 阈值。** 这是同一模式第三次出现（SQT2：naive 打败 hazard；离线：onset_wait 打败 green_age）。

关于 `q*=0.6` 顶在网格边界，**不需要扩网格，有封闭论证**：`never_wait` (0.9174) 已优于网格内最优 (0.8249)，扩网格方向是 `q*→1`，而 **`q*=1` 的极限就是 `never_wait` 本身**（阈值取到 1 意味着永不触发延迟）。所以扩网格能拿到的最好结果已经知道了。

记录为：**绿窗 hazard 臂在准确率口径下劣于 naive，最优阈值退化到边界，边界外的极限即 naive。**

⚠️ 但准确率 ≠ 碳。若在线检验与离线标定冲突，说明准确率口径漏掉了碳权重 —— 那同样是有价值的发现。
