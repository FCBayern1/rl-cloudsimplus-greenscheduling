# TB12 反事实重放 → harness 保真度缺陷诊断（2026-08-22 深夜）

按 Codex 裁定第 1/3 步执行(L_exec 测量 + 逐格反事实重放),结果推翻了
我方对 15 个输格的原解释,并定位到一个 harness 级根因。**第一轮判决不受
影响(它是"该 harness 下"的诚实测量);受影响的是第二轮设计。**

## 1. L_exec 实测:执行延迟解释被推翻

30/30 样本全链路(planned→步边界→dispatch):
- dispatch − 步边界 = **精确 1.0s**(确定性)
- slip = 量化残差 + 1s;**clair 的窗口释放本来就行对齐 ⟹ slip = 1 秒**
- 冻结 `calib/tb12_lexec.json`: L_exec = 601s(上界;对齐计划实际 1s)

"执行延迟削紧窗"不成立 —— clair 的紧窗计划没有被延迟削过。

## 2. 反事实重放:离线与仿真在 12/18 格判定相反

用实测确定性 slip 重放 15 个输格 + 3 个赢格:绝对碳差 2–6 倍
(off=3976: 重放 0.029 vs 仿真 0.166)。单位换算已用无风窗校验
(0.31625 逐位吻合)—— 分歧在风,不在记账。

## 3. 排除链

| 假设 | 检验 | 结论 |
|---|---|---|
| 执行延迟 | L_exec 实测 1s | ❌ |
| 固定行错位 | K 扫描: K* = +22/−15/−22/+17/+14,非常数 | ❌ |
| 时间戳跳变 | T110 全年间隔精确 600s,零偏离 | ❌ |
| 任意平移 | 逐步绿电互相关:无 K 可对齐(最佳误差≈均值量级) | ❌ |

关键观测:仿真绿电均值只有离线的 **56–73%**,且**滑过深谷**
(离线 23.5→18.1→4.6W 的深谷,仿真读 40.6/39.8/32.2W)。

## 4. 根因:三次样条在锯齿风电上振荡 + 负值截断

```java
powerSpline = new SplineInterpolator().interpolate(timePoints, powerValues);  // 三次
double powerW = Math.max(0, powerKW * 1000);                                  // 截断
```

- REAL_TIME 节点确在 600s 网格(时间戳解析已验证正确)
- 但采样/能量记账不在节点上 → 读到三次样条段中间值
- 真实 SDWPF 锯齿剧烈(相邻行 0↔300kW)→ 样条深谷侧**下冲为负** →
  被 `max(0,·)` 截断 → **绿电系统性被偷走**,幅度随当地锯齿度变化
- gwo1 合成风(1500s+ 平滑方块)从未暴露:样条无处振荡

一次性解释全部现象:均值衰减、滑谷、不可平移对齐、偏移相关、
以及 clair(紧窗计划)受害重于反应式盲。

# 修复实施与四层一致性门（2026-08-23 凌晨,Codex 九步序列 1–4 完成）

## 第二个 harness bug:DST 删行平移(修 STEP 时被门抓出)

三层门首跑:off=8000 逐位、off=26000 差 89.6W —— 错位有分界点。
根因:`Timestamp.valueOf` 用 JVM 本地时区(-Duser.country=GB),
**2021-03-28 01:00–01:50 六行在 Europe/London 不存在**,解析后与 +1h 行
撞车,样条去重**静默删 6 行**,此后全年数组平移(空洞实测 row 12389,
恰在 8000 与 26000 之间;10-31 回拨 row 43637 第二处)。
Python 审计扫不到:datetime 时区无关。合成风时间戳全部重复不过 DST 边界,
gwo1 一族从未暴露。

## 修复

STEP/LINEAR 使用**文件行序原始数组 + 纯行号模运算**:不解析语义时间戳、
不去重、不经时间域 wrap —— "row i = [i·600,(i+1)·600)" 由构造保证。
SPLINE 传统路径一字未动(历史复现)。能量账 `getIntervalEnergyWh` 逐行
重叠积分(非 STEP 复现旧算术,逐位兼容)。12 个 JUnit 全绿。
