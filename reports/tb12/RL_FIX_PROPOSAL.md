# TB12 RL 负结果:场景可用性评估与修复提案(供 5080/Codex 裁定)

日期:2026-08-25。前置:`RL_PAIR_VERDICT.md`(负判决,commit 0d3ee8f)。
本文回答三个问题:场景还能用吗、能修吗、修什么。**本文只提案,不动手**——
奖励函数属于实验定义,任何改动需要新预注册与 Codex 裁定。

## 一、场景本身完好,负结果不打击测试床

- T114+115 六门认证(池化 −17.51%)用的是冻结解析策略链,与 RL 奖励通道
  零耦合,**认证不受影响,继续封存**。
- 一致性门(obs==行值、能量==积分 0.001%)、接线哨兵、A′ 隔离负控全部在环
  且全过——环境物理和身份没有任何问题。
- RL 失败的每一环都定位在**奖励整形层**(Java 端 reward shaping),不在仿真
  物理、不在 obs 管线、不在 eval 头(同一 ModuleHead 管线在 h1/gwo1 探针正常)。

TB12 反而因此更有价值:它是一个能干净暴露奖励设计缺陷的稀疏决策基准——
gwo1 的高流量结构把这些裂缝压住了,TB12 把它们全部打开。

## 二、故障机制回顾(三条裂缝 + 一个失去的反制)

1. **归一化棘轮**:碳惩罚 Ĉ = min(step_kg / runningMax, 3.0),runningMax
   跨 episode 持续累积(`MultiDatacenterSimulationCore.java:1920`)。分母只涨
   不跌 → 同样行为的惩罚随训练机械缩水,"回报改善"可以与行为无关。
   实测:fc 全部真实奖励增益 +8.9 == 碳项改善 +9.1,而真实 kg 全程平坦。
2. **削顶套利**:比值封顶 3.0 → 把排放集中到少数几步,超过 3×runningMax 的
   部分免罚;分散释放每步按比例挨罚。defer-爆发式释放在惩罚空间占优。
3. **折扣套利**:γ=0.99、288 步,把碳推迟 150 步 ≈ 惩罚打 0.22 折。物理碳
   守恒,折扣后奖励不守恒 → 推迟本身净赚(v32_adv_defer 由 −0.88 翻正)。
4. **反制缺位**:TB12 仅 5 作业,completion 项整集才 0.3;
   `defer_deadline_force_mode: latest_start` 兜底保证作业必然完成 → 无限推迟
   零风险。gwo1 里吞吐项的强反推在这里不存在。

另:训练期 fc 真实 kg(0.1587)从未好于 nofc(0.1549)。"fc 训练更好"只在
奖励空间成立——这是奖励通道与物理量解耦的直接证据,不是预报无价值的证据。

## 三、修复提案(按必要性排序,缺一则漏洞仍在)

**R1 碳项去归一化**:碳惩罚直接用未归一化的 step Δkg(乘固定系数),或
carbon_normalization_mode=FIXED、分母从校准段冻结;**去掉 3.0 封顶**。
消灭棘轮与削顶。基础设施已存在(FIXED 模式已实现,只差配置+系数标定)。

**R2 碳的 credit 不过折扣**:任选其一——
  a) episode 终局加一项 −k·total_kg(终局项对释放决策做全局 credit);
  b) 释放动作按**物理边际 kg** 计费(per-slot marginal-kg 机制在 Java 端
     已有 `stepMarginalCarbonKg`/`per_slot_credit` 基建,改为用它做 r_i);
  c) 碳分量单独用 γ→1。
推荐 b:与决策粒度对齐,且复用现成代码。

**R3 训练期健康门(这条不需要裁定,属于监控不是实验定义)**:
  - 奖励-物理同向门:每个 checkpoint 检查 return 改善与 total_carbon_kg
    的同向性,背离即止损(与 5080 的 crd_dr≡0 止损同类,两列日志现成);
  - argmax 探针:每 N 迭代用 argmax 在 5 个固定偏移上滚一遍,报 kg vs
    greenfollow——训练/eval 行为差距(采样掩盖 argmax 坍缩)当场可见;
  - defer 率监控:argmax 下 defer 占比 >95% 连续 K 个 checkpoint 即报警。

**可选 R4(结构性,代价更大,仅当 R1+R2 后仍失败再议)**:动作抽象改为
按作业直接选释放行(5 作业 × 离散时行),把稀疏 credit assignment 问题
从 288 步时序上摘掉。这是换实验,不是修复。
